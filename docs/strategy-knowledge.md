# 策略与书籍登记基础

当前提供本地 Python 服务、桌面桥接接口及“书籍资料”“策略管理”页面。登记原文不触发解析、OCR、索引或模型请求，也不产生策略信号。具体试点、书籍选择和回测标准仍以 `stockseek-platform-todo.md` 的 A01–A06 为准。

## 书籍登记

从侧栏打开“书籍资料”，填写七项登记信息后点击“选择文件并登记”，在系统文件选择框中选择一个 PDF 或 EPUB。取消选择、登记失败或重复提交均保留表单内容，便于核对或继续登记；表单草稿仅在本次窗口中保留，登记记录则持久保存在工作空间。相同文件的元数据有冲突时拒绝登记，并提示核对。

下方列表展示已登记书籍，展开“版本与来源详情”查看完整元数据、文件名、大小、登记时间和指纹。“核验原文快照”显示本次核验状态和时间；重新打开应用后需要再次核验，不把旧核验结果当作当前完整性证明。读取失败显示错误与刷新入口，不显示成空书库。登记、成功发布的文本版本和语义索引分别展示。

`BookRegistry` 使用当前 `DesktopStore` 工作空间。`register(path, metadata)` 接受 PDF 或 EPUB，要求完整填写以下非空文本：

| 字段 | 含义 |
| --- | --- |
| `title` | 书名 |
| `author` | 作者 |
| `translator` | 译者；无译者请显式填写“无” |
| `language` | 语言 |
| `edition` | 版次或版本说明 |
| `source` | 文件取得来源 |
| `usage_scope` | 本次使用范围 |

文件以流式复制时实际读到的字节计算 SHA-256，快照保存在工作空间 `books/originals/<sha256>`，登记信息保存在 `workspace.sqlite3`。原文件路径不写入登记记录，仅保留原文件名。仅检查 PDF 文件头或 EPUB 的 ZIP/mimetype；不代表文件可完整解析、OCR 成功或内容已核对。

相同内容、相同登记信息重复提交返回 `duplicate=true` 和原登记，不创建新身份。相同内容填入不同元数据会报错，要求先核对；不会静默覆盖旧信息。不同内容独立登记，译本和修订版不会因书名相同而合并。返回的 `registered_at` 是本地登记时间，不是出版时间或历史上可获得该资料的时间。

`list_books()` 与 `get(book_id)` 读取登记；`verify(book_id)` 单独核验快照，返回 `original_status`：

- `available`：字节指纹一致。
- `missing`：快照缺失。
- `changed`：快照内容与登记指纹不同。
- `unreadable`：权限或其他读取错误。

核验结果不会覆盖登记或假称修复成功；登记快照中的 `parsing` 和 `indexing` 保留登记时的 `not_started`，当前解析能力需读取独立文本版本表，不能用登记快照推断。重复登记也不会修复缺失或损坏快照，需单独调用核验接口。没有删除、替换、自动下载或向云端发送接口。

桌面桥接提供 `register_book(metadata)`、`list_books()`、`get_book(book_id)`、`verify_book(book_id)`。登记必须经原生文件选择框选择一个文件，前端不能直接传任意文件路径；取消返回 `cancelled=true`，没有窗口则返回错误。沿用已有 `{ok, data/error}` 响应契约。

## 本地文本解析与位置引用

在书籍下点击“解析 / 重建文本”，显式提取已登记快照的文本。PDF 使用现有 `a-shares` 可选依赖中的 pypdf；EPUB 使用标准库按 OPF spine 阅读顺序解析 XHTML。此入口完全离线，不执行书中指令或脚本，不请求模型或云端，不支持加密 PDF、OCR、图表、公式、复杂版面关系或自动翻译。`text_only` 仅表示各位置提取到文字，不能证明文字完整、顺序正确或图表已识别；存在空白位置标为 `partial/no_text`。

PDF 位置是从 1 开始的**文件页序号**，印刷页为未知；EPUB 位置是从 1 开始的**阅读顺序章节**及 ZIP 成员路径，不伪造页码。引用完整显示该位置提取文本，不把检索片段或生成解释冒充原文。人工核对版面和图表仍需原书。

每个成功解析版本存入 `workspace.sqlite3` 的 `book_parses`，绑定书籍身份、原文件 SHA-256、登记元数据、解析器版本和全部提取位置；上述内容规范 JSON 的 SHA-256 即 `parse_id`，同结果重复解析返回原记录和原时间。更换提取结果或解析器版本新增记录，旧引用继续指向原解析版本。解析失败不发布半成品，不覆盖原文或旧文本；没有任务取消、断点续传、OCR 索引或自动重试调度。当前为同步本地操作，界面显示处理中。

输入关键词后选择解析版本检索；所有以空格分隔的词均需在同一位置按大小写无关的字面匹配，中文词组需按原文输入。最多返回 50 个位置并报告完整匹配数。没有多语言语义召回、分词、重排、翻译或自动回答；零命中只表示当前文本关键词未匹配，不能推断原书没有答案。点击“查看完整位置与出处”读取确切版本，并重新核验原文快照状态。原文后来缺失或改变时，旧提取文本仍可追溯并显示当前缺口。

服务为 `BookTextLibrary.parse(book_id)`、`history(book_id)`、`search(parse_id, query)`、`citation(parse_id, ordinal)`；桥接对应 `parse_book_text`、`book_text_history`、`search_book_text`、`book_text_citation`。原文件上限 256 MiB、章节 XML 单体 8 MiB、提取文本合计 32 MiB、位置 10000；超限拒绝发布。EPUB 不解压到文件系统，不访问远端章节，拒绝实体声明和越界章节路径。真实中文扫描、英文、跨页图表与复杂 EPUB 的质量评测仍待书籍和验收题集。

## 策略管理

从侧栏进入“策略管理”，点击“新建策略”，填写名称即可保存范围草稿。按需补充来源、市场、股票池、周期、持有期限、适用环境，以及观察、确认、执行时点和成交价格规则。页面不预选这些内容。

入场、过滤、退出、失效、仓位、组合、例外分别添加规则，每条记录内容、出处或个人说明、来源类型和定义状态。手工新增规则默认属于“个人规则 / 待定义”，应按实际出处调整；不把模糊条件自动转换成阈值。新增规则必须填写内容及出处才能保存。尚无例外等情况也需显式记录核对结论，空分类不能用于确认。

“保存新版本草稿”追加一个版本。离开页面保留本次窗口中的未保存编辑；关闭窗口会丢失未保存编辑。写入失败仍保留编辑，遇到版本冲突应先核对当前保存版本，再决定保留哪些修改。可以先复制未保存的内容，再“放弃未保存编辑”并重新打开最新版本。

“查看版本与规则”展示保存时的范围、七类规则、出处和全部历史版本；历史版本只读。最新草稿的确认需要填写确认人，并勾选已逐项核对；缺少范围或任一规则分类、仍有待定义规则时，服务拒绝确认。存在未保存编辑时不提供确认入口，避免把编辑内容误认为已确认的版本。

确认单独追加版本，保留确认人、时间及所对应的草稿版本。确认、实现、回测和样本外验证分别展示；当前实现未完成，回测和样本外均未评估。再次编辑已确认定义时，保存的是新的草稿，必须重新核对确认。刷新列表不会修改保存的定义，读取失败会显示错误，保留已有列表。

策略执行和跨规则冲突检查尚未实现；页面没有交易或策略回测入口。运行证据登记基础如下，不代表已完成策略验证闭环。

`list_strategies()` 返回各策略最新版本，`strategy_history(strategy_id)` 返回该策略从新到旧的全部版本。指定历史版本仍使用 `get_strategy(strategy_id, version)`。这些接口与保存、确认接口共用追加版本表；列表不会将草稿转换为已确认规则，也不会改变实现、回测或样本外状态。

## 运行证据登记

策略版本详情中的“读取 / 刷新本版本证据”只读取当前选中版本的记录。可展开查看数据指纹、参数及出处、代码版本、运行时间、指标、假设和限制。尚未读取、读取失败和无登记记录分别显示；无记录不表示没有风险。窗口中的查询结果需主动刷新，不代表外部文件当前完整性。

当前登记入口为本地服务 `StrategyRunRegistry.record(strategy_id, version, manifest)`，桌面桥接为 `record_strategy_run(strategy_id, version, manifest)`；尚无图形登记表单、导入器或运行调度。查询使用 `list_runs(strategy_id, version)` / `list_strategy_runs(strategy_id, version)`。

必须指定确切的已确认版本；布尔、浮点、空版本及草稿均不能登记。后续保存新草稿不影响历史版本证据。记录在 SQLite 中追加保存，附带登记时间和该版本定义的规范 JSON SHA-256；同一策略、同一版本、同一 `run_id` 提交相同内容返回原记录，内容不同则拒绝覆盖。修正记录请使用新编号并在说明中引用旧编号，旧记录保留。

`manifest` 必须包含以下字段，不能省略失败或不确定状态：

| 字段 | 契约 |
| --- | --- |
| `run_id` | 1–128 字符，首字符为字母或数字，其余允许字母、数字、点、下划线及连字符 |
| `stage` / `outcome` | `backtest` 或 `out_of_sample`；结果为 `completed`、`failed`、`cancelled`、`inconclusive` |
| `recorded_by` / `summary` | 非空登记人及结果说明；失败时说明原因 |
| `implementation` | 非空 `entrypoint` 与 `revision`，由调用者提供实现入口及代码版本 |
| `parameters` | 参数名映射到 `{value, source}`；每项必须记录值与非空出处或假设；无参数使用 `{}` |
| `data` | 非空列表，每项含非空 `source`、`version` 和 64 位小写十六进制 `sha256` |
| `period` | `start`、`end` 为 ISO 日期，起日不晚于止日，表示样本区间 |
| `started_at` / `finished_at` | 含时区的 ISO 运行时间，起点不晚于终点 |
| `duration_seconds` | 非负有限数值，由调用者提供实际耗时，允许与起止墙上时间之差不同 |
| `metrics` | 指标名映射到 `{value, unit}`，数值必须有限，缺失明确用 `null`；无指标使用 `{}` |
| `assumptions` / `limitations` | 非空文本列表；无额外假设或限制也需显式写明核对结论 |

所有记录固定标为 `external_unverified`。登记只验证结构，不执行代码、不复制或核验所声明的数据/代码文件，也不检查实现是否符合规则、数据是否存在未来泄漏、指标计算是否正确。参数与定义之间的语义一致性仍需核对。即使 `outcome=completed`，策略的实现状态仍为 `not_implemented`，回测及样本外状态仍为 `not_evaluated`；失败、取消和不确定记录也不能当作验证通过。完整验证状态提升与可复现运行器尚未实现。

## 已确认策略的离线条件检查

已增加独立的逐条条件计算服务与桌面桥接接口：`check_strategy_conditions(strategy_id, version, as_of, data)`、`get_strategy_check(check_id)`、`strategy_check_history(strategy_id, version)`。只计算已确认版本内的明确比较表达式，保留完整输入和历史可得时间选择证据；人工、缺失、规则无效和未实现分别显示。计算不提升实现或验证状态，不生成交易指令。表达式、数据契约及尚未实现范围见 [条件检查说明](strategy-conditions.md)；当前没有页面入口或供应商数据自动接入。

## 备份范围和限制

关闭工作空间应用后，将整个工作空间目录作为一组备份和恢复，至少同时保留 SQLite 数据库与 `books/originals/`。只复制数据库会丢失原文。跨平台恢复和备份工具的自动化验收尚未完成，不能据此标记 D07 完成。

书籍原文、登记数据库和个人使用说明不应提交源码仓库。开发测试使用临时目录和合成文件；真实书籍解析、引用页码、检索质量及多平台文件选择器仍待实际资料和环境验收。
