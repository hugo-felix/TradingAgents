# TradingAgents 桌面应用：调研与设计提案

日期：2026-11-06。状态：用户已确认修订方案，首版已实施；运行与交付说明见 `docs/desktop.md`。下文保留调研与设计依据。

## 目标与现状

让用户打开应用后快速理解结论、主要依据与不确定性，需要时再深入原始报告；支持 macOS 和 Windows，本地优先。

代码检查：`reporting.py` 汇总所有角色正文，`report_html.py` 按分析师、研究、交易、风控、最终决策依次全部展开。已有中国移动样本 `artifacts/600941_glm53flash_20261105/complete_report.md` 约 52,911 字符（UTF-8 文件约 97KB）。最终决策本身已有执行摘要、论据、反向证据和改变判断的条件，可作为摘要数据来源。

现有 `output/design/index.html` 与调研笔记是演示原型，可参考其低噪音信息层级；其中红利、持仓、盘前盘后等范围不自动视为本次已确认需求。正式应用必须接真实数据。

## GitHub 调研

本轮阅读官方仓库、许可证及文档，没有安装运行候选产品；性能和移植成本为架构判断，不是实测结论。实施前锁定版本并再次核对其许可和依赖。

三条路线：①当前项目 + pywebview（推荐）；②当前项目 + Tauri；③在 Wealthfolio 上增加研究模块。第一条在当前 Python 仓库中边界最少，第三条适合日后以账户管理为核心的不同需求。

## 首版范围与信息设计

主界面使用左侧历史列表、右侧报告详情；新建分析是独立表单，设置集中到一个入口。

1. **摘要默认展示**：股票和分析日期、模型最终评级、最多 120 个汉字的结论、最多三条核心依据、最多两条重要风险，以及会改变判断的条件。数据校验失败或关键数据缺失必须在首屏出现。
2. **依据按需查看**：点击摘要条目定位对应原文/证据，区分事实与模型解释；来源和数据截止时间随事实展示。
3. **全文单独打开**：按主题/角色切换，辩论过程默认收起；不在摘要下直接拼接几万字。
4. **历史与搜索**：按股票、日期、评级检索；列表分页，详情延迟加载；返回保留筛选和阅读位置。
5. **启动真实分析**：股票、日期、模型配置，运行中展示真实阶段和耗时，可取消、失败可重试；浏览历史不受运行影响。

摘要不得用机械截断造成结论反转；优先复用结构化输出或有明确标题的原文摘要。对于无法可靠映射的旧报告，只展示可追溯摘录并标识“摘要未结构化”，保留打开全文入口。不得伪造置信分数，不能把校验通过等同投资判断正确。

## 精简架构

`本地 HTML/CSS/JS 界面 → pywebview 白名单桥 → 报告服务 / 任务服务 → 现有 TradingAgents 引擎`

- UI：只负责展示、导航、筛选和局部更新；首版无需引入前端大框架。
- 报告服务：统一摘要数据契约，兼容现有 Markdown 和状态 JSON；新运行保存带版本号的摘要 JSON、原文及证据关联。
- 任务服务：独立 Python 子进程执行分析，通过事件队列传递阶段；一个活动分析任务，取消时回收子进程。失败和取消不生成“完成”报告。
- 持久化：沿用报告文件；SQLite 只存索引、任务状态及非敏感设置。使用唯一 run_id，避免同日重跑覆盖。
- 凭据：复用现有环境配置，桌面新增凭据使用系统凭据库；不传入网页、不写入报告与日志。
- 桥接安全：只暴露必要方法，限制文件路径到选定报告目录；报告内容作为不可信文本渲染，禁止脚本；外部链接交给系统浏览器。

无云端后台、账号系统或外部数据库。持仓管理、自动下单、多设备同步、定时监控不纳入本次首版。

## 跨平台交付与验收

参考 [pywebview 打包文档](https://pywebview.flowrl.com/guide/freezing.html) 和 [渲染引擎说明](https://pywebview.flowrl.com/guide/web_engine.html)：macOS 使用 WKWebView；Windows 固定使用 Edge WebView2，安装时检查运行时，不能退回旧 IE 内核。

- 分别在 macOS 与 Windows 构建并冒烟测试；macOS Apple Silicon/Intel 各自验证依赖，Windows 首版以 x64 为目标。
- 交付携带 Python 运行时的应用，用户无需安装 Python；源码启动成功不算安装包验收通过。签名、公证是否可完成取决于实际证书条件，发布状态如实标注。
- 使用现有长报告验证摘要长度、原文定位、缺失/失败状态、历史报告导入；保留报告质量门禁与评级一致性测试。
- 验证取消/重试、重复启动、重启后的中断状态、含中文及空格路径、离线打开历史。
- 交互目标：历史切换不重绘全文，长任务不阻塞窗口；在验收机器记录实际延迟，目标为已缓存切换 200ms 内、新窗口首屏 2 秒内，不含模型运行时间。

## 建议实施顺序

1. 报告摘要数据契约与真实历史报告读取。
2. 桌面窗口、历史列表、分层报告阅读及设置。
3. 分析启动、真实进度、取消与失败恢复。
4. macOS/Windows 构建、安装与真实交互验收。

## 结合现有原型的设计修订

本节是用户要求参考 `output/design/index.html` 后的修订，取代上文“历史列表作为主界面”的建议。已检查当前 HTML、状态与导航代码，并查看现有 `preview.png`；浏览器连接不可用，本轮未重新运行交互验收。以下是设计建议，尚非已实现功能。

### 产品骨架：沿用四页，以股票档案贯穿

保留“今日工作台 / 研究与观察 / 我的持仓 / 研究与决策记录”。股票档案是从这些页面进入的共用详情，分析任务是辅助页面，设置放在侧栏底部。首页面向变化，研究页面向股票，记录页面向时间，各自只有一种主要组织方式。

这比“历史报告列表 + 阅读器”更贴近原型的持续研究流程；也比首页同时摆满资产、图表和报告更容易抓住重点。单独的报告阅读器仍保留，作为股票档案的深入入口。

### 今日工作台：先回答今天有什么值得看

- 延续原型的深色、金色强调、安静留白及事项选中后才展开详情。
- 重要变化、个人条件、后续研究可保留分组，但每条事项只显示股票、变化、与原判断的关系及时间。多项时用紧凑列表，避免大卡片拉长页面。
- 数据检查范围与失败提示移到事项区上方，避免先看到“暂无变化”、后看到来源缺失。无法检查时明确显示“检查未完成”，不显示完成标记。
- 新增“研究已更新”事项，连接真实分析结果。没有监测服务时，首页只显示实际导入/运行产生的事项，不凭空制造新公告提醒。
- 桌面宽窗采用列表与详情双栏；选中时保持列表宽度和滚动位置稳定，避免从整行卡片突然缩为双栏。窄窗进入详情后可一键返回原位置。
- 盘前/盘后作为时间上下文，而非两套任务。跟随本地时间默认选择，允许回看，不要求每天记录。组合摘要、计划与复盘继续按需展开。

### 股票档案：补齐真正解决长报告的阅读设计

原型中的“为什么持有 / 原判断还成立吗 / 我的决定”有清楚的思考顺序，但会使未持仓股票语义不适用，且连续卡片仍可能增长成另一份长报告。改成固定股票标题区与四个页签：

| 页签 | 内容与层级 |
| --- | --- |
| 研究摘要（默认） | 最新模型观点、分析日期与校验状态；一句结论；至多三条关键依据；最重要的反向证据；改变判断的条件。有关联旧版本时先给出“较上次变化” |
| 事实与依据 | 盈利、现金流、分红、估值等主题；每项标注值、期间、来源及截止时间。点击摘要依据直接定位到对应项 |
| 我的判断 | 当前个人投资逻辑与观察条件；“记录决定”时才展开表单。保留模型建议和个人判断的区别 |
| 完整报告 | 主题目录与角色正文；辩论默认收起，支持搜索、导出与独立阅读窗口 |

股票标题区展示名称/代码、是否持仓、行情截止时间和“更新研究”主操作；股息率等指标仅在有可靠口径时显示。实际持仓缩为一行上下文，点击进入持仓页，避免右侧重复三块卡片挤占阅读宽度。正文使用 15–16px，辅助文字至少 12px，不能沿用部分原型中 10px 的文字密度。

“较上次变化”按评级、关键事实、判断条件比较；没有可靠旧版本时显示首次研究，不生成虚构差异。新事实不自动改写旧结论。只允许引用支持其含义的证据；无法结构化时使用明确标识的原文摘录。

### 研究、持仓和记录各自收敛

- 研究列表：股票、最新观点、关键变化/待核查点、研究日期为主要列；个人股息率条件作为可选列。不让固定红利指标盖过研究状态。支持名称/代码搜索，发起分析就近可见。
- 持仓：保留真实数量、成本与实收分红；维护和导入为次级操作。未知现金不算完整账户资产，模型建议不修改持仓。首版是否实现真实持仓维护仍需范围确认。
- 记录：按股票和类型筛选研究版本、个人决定及实际持仓变更；点击研究进入对应历史版本。普通操作日志继续折叠，不与重要判断混排。
- 分析任务：仅用户配置和运行时进入独立页面；运行后用顶部紧凑状态显示阶段、耗时及取消入口，完成时就近通知并进入新摘要，保留旧版本。

### 实现边界

四页导航不意味着引入四套服务。依然采用一个桌面程序，内部只有报告、任务和本地数据三类职责，复用当前引擎。真实监测需要独立定义检查范围、补查和去重规则，应在报告阅读与分析闭环完成后接入。

建议分两步交付：先实现四页外壳、真实研究列表/股票档案/历史版本、分析运行及双平台构建；然后接入确认需要的持仓、分红与变化监测。首页空状态应诚实说明当前可用范围，不用演示数据补齐功能。
