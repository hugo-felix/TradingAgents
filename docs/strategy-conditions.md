# 已确认策略的离线条件检查

`StrategyCheckRegistry` 和桌面桥接提供确定性的逐条条件计算。只接受一个明确的、人工确认过的策略版本；新草稿不能检查，旧确认版在编辑后仍能检查。该服务没有界面入口，不读取行情、不调用模型、不产生订单，也不改变策略的实现、回测或样本外验证状态。

## 定义表达式

在策略定义的某条规则内保存可选 `check` 字段；仍需填写原有 `text`、`citation`、`kind`、`state`。只有 `state=defined` 的明确表达式参与计算，例如：

```json
{
  "text": "最新收盘值高于最近三条观测的均值",
  "citation": "个人测试假设，非原书结论",
  "kind": "personal",
  "state": "defined",
  "check": {
    "op": "gt",
    "left": {"metric": "close"},
    "right": {"metric": "close", "aggregate": "mean", "window": 3}
  }
}
```

比较支持 `gt/ge/lt/le/eq`。操作数支持最新指标值、最近 N 条观测的算术均值（`window` 为 1–10000 整数），或含 `constant`、`unit`、`source` 的有限数值常量。例：`{"constant": 20, "unit": "CNY/share", "source": "个人测试假设"}`。左右单位必须逐字一致，不做币种、复权或单位换算。数值按输入 JSON 数字的十进制表示计算；均值使用精确有理数，证据值可能显示为 `1/3`，避免舍入改变比较边界。

没有从规则文字生成表达式的功能。`manual` 即使附带表达式也保留人工检查；没有表达式或未知运算显示未实现，格式错误显示规则无效。保存和确认仍属于定义管理，不保证表达式受到引擎支持。

## 输入数据和历史可得时间

桌面接口 `check_strategy_conditions(strategy_id, version, as_of, data)` 沿用 `{ok, data/error}` 契约。`version` 必须是确切的正整数；`as_of` 为含时区的 ISO 时间。`data` 必须明确以下全部字段，不接受额外字段：

```json
{
  "symbol": "000001.SZ",
  "market": "CN-A",
  "timeframe": "daily",
  "price_basis": "raw",
  "source": "synthetic",
  "revision": "fixture-v1",
  "series": {
    "close": {
      "unit": "CNY/share",
      "observations": [
        {"observed_at": "2020-01-02T15:00:00+08:00", "available_at": "2020-01-02T15:05:00+08:00", "value": 10},
        {"observed_at": "2020-01-03T15:00:00+08:00", "available_at": "2020-01-03T15:05:00+08:00", "value": 20},
        {"observed_at": "2020-01-04T15:00:00+08:00", "available_at": "2020-01-04T15:05:00+08:00", "value": 30}
      ]
    }
  }
}
```

所有记录必须包含观测时刻、可得时刻和数值或 `null`；时间需带时区，可得时间不能早于观测时间。每个指标内相同观测时刻与可得时刻的重复或冲突记录会被拒绝。等价时区按同一时刻处理。总量上限 100000 条，不接受布尔值、数字字符串、NaN 或无穷值。

计算仅选择观测时刻和可得时刻都不晚于 `as_of` 的记录；同一观测时刻选届时最新修订。后续修订、未来行情均不能参与。最新修订为 `null` 时不退回旧值；均值窗口有缺失或数量不足时显示数据不足，不填补、不跳过。零值是有效数值。未来记录仍需通过输入格式校验。

## 结果和留存

七类规则都返回原规则、分组、序号及独立状态：

| 状态 | 含义 |
| --- | --- |
| `met` / `not_met` | 该条比较成立 / 不成立 |
| `manual` | 保留人工检查 |
| `insufficient_data` | 截止时刻缺少指标、观测不足或含缺失值 |
| `not_implemented` | 没有明确表达式或不支持该运算 |
| `invalid_rule` | 表达式格式、参数或单位不一致 |

`invalidation` 分组的 `met` 仅表示失效条件这条比较成立；不能汇总成“策略通过”。结果保留实际参与计算的观测、单位和常量出处，完整输入、定义指纹、输入指纹、引擎版本和检查时刻一并持久保存在当前工作空间 SQLite 中。

相同身份、策略版本、定义、输入、截止时刻和引擎版本重复计算返回原检查快照；并发提交不新增重复记录。修改输入或策略版本生成独立检查。`get_strategy_check(check_id)` 读取完整快照，`strategy_check_history(strategy_id, version)` 读取该版本的摘要列表。没有覆盖或删除接口；返回对象修改不影响已存快照。随工作空间数据库备份，关闭应用后复制整个工作空间的既有约定仍适用。

## 尚未验证的范围

数据固定标记 `caller_supplied_unverified`。来源、可得时刻、修订和价格口径由调用者声明；本服务未接入供应商原始档案核验。只自动检查市场和周期与策略定义一致，股票池、环境、价格口径、指标单位含义仍需人工核对。数据过期阈值尚未设置，旧观测不会自动失效。

最近 N 条观测不保证连续交易日、交易所日历或完整周线；也未实现观察—确认—执行日分离、下一交易日成交、停牌/涨跌停约束、组合和费用、回测、样本外评估。引擎版本标识不是代码归档或完整运行环境快照。该功能只交付条件计算基础，不能据此完成 S06、V02、U02 或 U03 整项验收。
