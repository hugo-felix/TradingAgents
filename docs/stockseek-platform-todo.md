# StockSeek 产品路线与 TODO

更新日期：2026-11-09（Asia/Shanghai）
状态：需求与交接清单；不代表下列功能已实现。
基线：`0a0ff90`，本机与远端 main 在整理时一致。另一台电脑未推送的迭代不在本清单核查范围内。

## 目标与边界

建设个人投资研究、策略与决策管理工作台，贯通：市场跟踪 → 深度研究 → 策略知识 → 规则确认 → 策略验证 → 计划跟踪 → 真实记录 → 复盘。

效果优先：优先保证原文理解、规则完整性、证据追溯、适用边界与样本外验证；允许独立计算后台和较长的入库过程。不能用回答流畅、框架复杂或检索评分代替策略有效性。

首阶段人工在券商端执行，StockSeek 记录、导入和复盘。券商下单、自动交易及完整账户系统不属于首阶段承诺。

## 已有基础（避免重复建设）

- TradingAgents 多维分析与讨论流程，A 股数据适配与事实引用链路。
- AKShare、yfinance 数据入口；公告、估值、宏观等已有路由，具体覆盖以代码为准。
- StockSeek 本地桌面界面：Python、pywebview、SQLite。
- 报告版本与原文阅读、个人判断、手工持仓快照、后台分析任务。
- A 股决策计划字段与条件展示；已有决策结果评分回测。
- 尚不能将决策评分回测视为包含逐笔订单、成交约束和完整账户的策略回测。

参考：`docs/desktop.md`、`docs/superpowers/specs/2026-11-06-decision-quality-design.md`。

## 第一里程碑：一个策略闭环（P0）

依赖顺序：范围确认 → 数据与知识样本 → 规则核对 → 回测与独立评估 → 股票条件检查 → 复盘。

### A. 明确试点与资源

- [ ] A01 确认首个市场与股票池：建议先 A 股；明确 ETF、ST、次新、停牌与退市证券的处理范围。
- [ ] A02 确认首个策略单元及周期：建议从《笑傲牛熊》的周线趋势方法选择一个边界明确的单元，尚未最终定案。
- [ ] A03 确认实际书籍文件、作者、译者、语言、版次、来源及使用范围；内容来源本身不意味着可公开分发。
- [ ] A04 确认计算资源、是否允许云端处理、模型费用预算、可接受入库及查询耗时。
- [ ] A05 预先确定基准、成本、样本内/外区间、风险指标与验收标准；不事后按最好收益调整标准。
- [ ] A06 确认策略知识是辅助判断还是进入确定性条件检查；两者以独立状态展示。

验收：上述决策有记录；未确定事项明确标注，不由实现者默默补齐。

### B. 市场数据与交易语义

- [ ] B01 盘点已有数据接口的覆盖、来源、费用、限流与失败策略，优先扩展已有适配层。
- [ ] B02 统一证券代码、市场、币种、时区、交易日、单位、复权口径、成交量与成交额语义。
- [ ] B03 接入试点需要的个股、基准指数和行业历史数据；显示来源、覆盖区间与更新时间。
- [ ] B04 区分事实发生日、首次公开日、系统获取日与修订版本，满足历史时点查询。
- [ ] B05 处理停牌、涨跌停、退市及历史股票池；历史成分不可用时，明确幸存者偏差，限制结论范围。
- [ ] B06 对行情缓存、重试、数据陈旧、源切换和口径差异建立可见状态；失败不填零、不冒充无变化。
- [ ] B07 明确分红、拆并股和其他公司行动对信号价格、成交价格与收益计算的影响。

验收：同一策略使用一致数据口径；历史查询不能读到当时尚未公开的信息；缺失项可追查。

### K. 原书知识库与检索质量

- [ ] K01 书籍登记：作者、版本、语言、文件指纹；重复文件识别，译本及修订版保留独立身份。
- [ ] K02 选择图表丰富、中文扫描、英文正文等代表页面，对比 Docling / MinerU 的解析效果。
- [ ] K03 保留章节、段落、页码/位置、图表、图注、公式和相互关系；记录 OCR、缺页及结构识别失败。
- [ ] K04 区分 PDF 文件页码与印刷页码；EPUB 使用章节及位置，不编造固定页码。
- [ ] K05 原文件、解析产物和模型解释分别保存；记录解析器、模型及版本，支持重建与增量更新。
- [ ] K06 支持取消、失败重试、进度恢复；索引完成前不显示入库成功，避免影响现有研究任务。
- [ ] K07 建立关键词＋多语言语义＋重排序检索，优先按书籍、策略、周期与市场过滤。
- [ ] K08 检索同时召回规则、限定条件、反例与相关图表；必要时回到完整小节和原图。
- [ ] K09 中文问题可检索英文原文；建立投资术语别名，保留原术语及翻译区别。
- [ ] K10 回答引用定位到书籍版本与原文位置；点击可预览，模型不能编造页码或引用。
- [ ] K11 区分原书陈述、系统解释、个人规则和实时市场事实；书籍内容作为资料，不作为执行指令。
- [ ] K12 未找到充分依据时明确无法判断；跨书冲突展示不同假设，不默认拼接规则。
- [ ] K13 记录文档删除、替换、索引重建及嵌入模型变更；旧报告引用保留可解释的快照或缺失说明。
- [ ] K14 清楚说明本地/云端处理范围；仅在明确配置后向云端发送原文或图像，记录相关费用。

验收：用人工核对题集验证出处、跨页条件、图表依赖、中英文检索、反例及无答案问题；覆盖率与错误率分别统计。

### S. 策略定义与版本管理

- [ ] S01 建立策略实体：来源、版本、市场、股票池、周期、持有期限及市场环境。
- [ ] S02 完整记录入场、过滤、退出、失效、仓位、组合限制及例外条件。
- [ ] S03 明确信号观察时间、确认时间、可交易时间和成交价格规则；禁止用收盘信号回填当日可成交价。
- [ ] S04 分离作者原意、模型提取草稿、人工解释、量化阈值及 A 股适配假设，逐项附出处。
- [ ] S05 原书未明确“放量”等阈值时保留待定义状态，不自动宣称某个数值来自原书。
- [ ] S06 草稿经人工确认后才进入可执行规则；主观条件保留人工检查或不可量化状态。
- [ ] S07 状态分离：文献方法 / 已确认规则 / 已实现 / 已回测 / 已样本外验证；验证状态不等于保证获利。
- [ ] S08 修改规则生成新版本，并绑定数据、参数、实现、验证记录；保留当时用户采用的版本。
- [ ] S09 策略冲突显式展示：趋势、价值、短线等不同体系分别检查，不直接平均评分。

验收：第三人可依据策略定义复现信号；每项参数有来源或假设标签；未确认规则不会生成确定交易条件。

### V. 策略回测与评估

- [ ] V01 确定回测契约及引擎；与既有 LLM 决策评分回测明确区分，复用可用部分。
- [ ] V02 由确定性代码计算指标、信号和约束；模型解释不代替计算。
- [ ] V03 建模 A 股 T+1、交易日、买卖数量约束、费用、滑点、停牌、涨跌停无法成交及部分成交假设。
- [ ] V04 检查未来数据泄漏、历史公开时间、复权与公司行动、股票池偏差和数据修订。
- [ ] V05 在固定股票池、时间窗和数据条件下比较简单基线及基准，记录不可比因素。
- [ ] V06 分离开发、调参与样本外区间，采用合适的滚动验证；记录试验次数，控制择优与过拟合。
- [ ] V07 评估收益、回撤、波动、换手、暴露、交易数、盈亏分布及集中度；提供样本量与不确定性。
- [ ] V08 检查参数敏感性、交易成本变化、市场阶段和不同股票子集；说明利润是否集中于少数样本。
- [ ] V09 运行结果保存策略/代码/数据版本、参数、成交明细、假设、耗时及失败记录，支持复现。
- [ ] V10 知识库效果与策略效果分别评估；Ragas 或模型评分不能证明投资优势。
- [ ] V11 对照不使用知识库的研究/策略流程，衡量新增知识是否提升规则完整性、适用性判断与复盘质量。

验收：在明确约束下复现信号与交易结果，公开失败及不显著结果；样本不足时不宣称策略有效。

### U. 首个股票条件检查

- [ ] U01 股票页展示策略版本、适用周期、环境、验证范围和数据时间。
- [ ] U02 每项条件呈现满足 / 未满足 / 失效 / 数据不足 / 需人工判断，附计算值和依据。
- [ ] U03 同时提供书籍出处和当前市场事实，不将书中原则当成当前股票证据。
- [ ] U04 使用图表关联研究日期、策略信号及真实操作；防止视觉上暗示事前已知的后验信号。
- [ ] U05 明确下一观察条件和计划有效期；中期评级不自动变成次日开盘操作。
- [ ] U06 保存一次完整试点记录：规则确认、回测、当日检查、个人判断与后续复盘。

验收：一个真实股票示例可从条件检查逐层追溯到数据、规则、原文与验证记录。

## 第二里程碑：持续跟踪与研究融合（P1）

- [ ] M01 管理自选股和实际持仓，分别表达观察意图和账户事实。
- [ ] M02 每日巡检行情、公告、新闻、市场与行业变化；候选事件未经核实不当作确定日历。
- [ ] M03 建立变化去重、重要性和数据覆盖状态；“没有发现”不等于“没有发生”。
- [ ] M04 首页展示今日变化、影响哪个研究假设/策略条件、是否建议重新研究。
- [ ] M05 明确深度研究触发条件、模型费用预算及人工/自动模式，避免默认全量反复运行。
- [ ] M06 向不同分析角色提供相关且有上限的知识；同源多 Agent 引用不当作独立验证。
- [ ] M07 在报告中保留最强反向证据、执行条件、有效期、失效条件及数据缺口。
- [ ] M08 实现计划条件跟踪与防抖；缺数据时暂停相关判断，不发送误导性条件命中提醒。
- [ ] M09 按需接入飞书等通知，带变化、来源、计划期限和应用内定位；支持静默与去重。
- [ ] M10 完善趋势、成交量和基准图表；评估 Lightweight Charts，按许可保留署名。
- [ ] M11 扩充书籍与策略前，复用首批评测集回归，检查新资料引入的观点冲突。

验收：从变化发现到研究更新、条件提醒和原文核查形成连续工作流；日常任务与知识入库互不阻塞。

## 第三里程碑：真实记录与决策复盘（P1/P2）

- [ ] R01 导入实际成交，保存券商标识、成交时间、价格、数量、费用及导入来源；建立幂等和重复检测。
- [ ] R02 区分计划、模拟成交与真实成交；模型不能反向改写已发生操作。
- [ ] R03 补现金、分红和公司行动记录后再提供完整收益；数据不全时限制账户绩效结论。
- [ ] R04 将操作关联当时报告、策略版本与个人理由；支持无法关联的历史记录。
- [ ] R05 分别评估研究方向、策略规则与个人执行；单次卖后上涨不直接认定决策错误。
- [ ] R06 区分价格收益、含分红总回报、资金加权及时间加权收益，按数据能力选择并说明。
- [ ] R07 展示相对基准表现、计划遵守情况及归因不确定性，不编造因果解释。
- [ ] R08 复盘产生个人规则草稿，经确认和版本记录后使用，不能追溯修改过去知识状态。

## 未来独立评估：券商执行与完整账户（P3，未承诺）

- [ ] X01 先评估只读账户/成交同步、权限和对账，再决定是否接入交易执行。
- [ ] X02 若支持下单，设计人工确认、订单状态、撤单、成交回报、幂等和网络异常恢复。
- [ ] X03 建立交易前风险校验、现金/冻结资金/可用数量、异常熔断与审计。
- [ ] X04 先模拟与影子运行；实盘和自动执行需独立范围确认，不因本文自动获得授权。

## 技术候选与选型原则

下列仅为调研候选；不要求全部安装、整套接入，也未证明任何组合对本项目最佳。

| 领域 | 候选/参考 | 核查重点 |
| --- | --- | --- |
| 每日巡检与通知 | https://github.com/ZhuLinsen/daily_stock_analysis | 选择性复用；2026-11-09 核查时 AKShare 版本约束与本项目冲突，不能直接合并依赖 |
| 文档解析 | https://github.com/docling-project/docling ; https://github.com/opendatalab/MinerU | 实际扫描、图表、章节、页码质量；模型依赖、许可和计算成本 |
| 多模态知识 | https://github.com/HKUDS/RAG-Anything | 图文关联、反例召回、原文定位、关系抽取错误及维护成本 |
| 对照基线 | https://github.com/infiniflow/ragflow | 同数据同题集比较质量；部署、备份与资源需求 |
| 嵌入与重排序 | https://github.com/FlagOpen/FlagEmbedding | 中文问英文书、术语、召回、重排序、延迟及模型许可 |
| 检索存储 | https://github.com/lancedb/lancedb ; https://github.com/asg017/sqlite-vec | 由质量、过滤、规模和运维验证决定，不预先锁定；sqlite-vec 仍 pre-v1 |
| 原文预览 | https://github.com/mozilla/pdf.js | 本地引用定位、跨平台、图表与页码 |
| 图表 | https://github.com/tradingview/lightweight-charts | 研究/信号/操作标记、数据口径与署名 |
| 知识评估 | https://github.com/vibrantlabsai/ragas | 自动评分结合人工原文核验，不用于证明盈利能力 |
| 策略回测 | https://github.com/nautechsystems/nautilus_trader ; https://github.com/mementum/backtrader | 依首个策略决定，A 股约束、可复现性和历史数据覆盖 |
| 后续因子研究 | https://github.com/microsoft/qlib | 仅在因子、模型训练或股票池排序需求明确后考虑 |

建议保持 StockSeek 为统一界面，知识与计算能力允许独立后台部署；本地或远端的选择在 A04 后确定。知识检索接口与具体引擎隔离，以便用评测结果更换实现。

## 首批验收与交接产物

- [ ] D01 范围决策、首个策略规范和原文核对记录。

- [ ] D04 技术方案对照结果：相同书籍、题目、模型条件；记录质量、耗时、费用和资源占用。
- [ ] D05 回测与样本外报告、可复现配置及全部重要假设，包含未通过或不确定结果。
- [ ] D06 一只股票的端到端演示，能打开原文、条件证据、历史策略版本和复盘记录。
- [ ] D07 备份、恢复、版本迁移、失败重试及部署说明；验证 macOS 与 Windows 前端连接和任务状态。

完成条件：任务勾选必须附可核查证据；不把设计完成、文档存在或单平台通过当作整个平台已完成。
